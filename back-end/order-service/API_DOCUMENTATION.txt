--------------------------------------------------------------------------------

Token alma:
    POST http://localhost:8180/realms/crm/protocol/openid-connect/token
    Content-Type: application/x-www-form-urlencoded

    &client_secret=crm-client-secret

    Authorization: Bearer <access_token>

NOT (bilinen ortam kuirku): Keycloak dev-mode'da token'in "iss" claim'ini
istegi hangi hostname ile aldiysa ona gore yazar. docker-compose.yml'deki
keycloak servisine KC_HOSTNAME=keycloak eklenmemisse, host makineden
(localhost:8180) alinan token'larin "iss"i container-ici servislerin
bekledigi (http://keycloak:8180/...) ile eslesmez ve her istek 401
"iss claim is not valid" doner. Bu order-service'in degil, infra'nin
sorunudur.

3. SIPARIS DURUMLARI (GNL_ST, entCodeName=CUST_ORD)
--------------------------------------------------------------------------------
    51  WAIT       Beklemede            (Configuration asamasinda duzenlenebilir)
    52  MIDLWARE   Siparis Alindi Isleniyor  (finish sirasinda gecici ara durum)
    53  FINISHED   Tamamlandi           (provizyon basariyla bitince)
    54  REJECTED   Reddedildi           (cancel sonrasi)

Akis: WAIT(51) --create/addItem/configuration--> WAIT(51) --finish--> MIDLWARE(52)
      --provizyon basarili--> FINISHED(53)
      WAIT(51) --cancel--> REJECTED(54)

Yalniz WAIT durumundaki bir siparis duzenlenebilir (item ekle/cikar,
configuration, finish, cancel). Baska durumdaysa 409 OrderNotEditableException.

4. ENDPOINT LISTESI (mantiksal sira)

--------------------------------------------------------------------------------
4.1) POST /api/v1/orders/validate-basket
--------------------------------------------------------------------------------
FR-017. Offer Selection'da "Next" - Configuration'a gecmeden once sepeti
dogrular. Hicbir kayit olusturmaz (read-only).

Request body:
{
  "custId": 1,
  "custAcctId": 1,
  "items": [
    { "prodOfrId": 1, "cmpgId": null, "charVals": [] }
  ]
}

Alan aciklamalari:
  custId        Long, zorunlu
  custAcctId    Long, zorunlu
  items         List, en az 1 eleman (NotEmpty)
    prodOfrId   Long, zorunlu - product-service'teki gercek teklif id'si
    cmpgId      Long, opsiyonel - product-service'teki gercek kampanya id'si
    charVals    List, opsiyonel (bu asamada genelde bos gelir)

Basarili yanit: 200 OK, govde yok.

Olasi hatalar:
  404  Customer {custId} bulunamadi (customer-service'ten)
  400  AccountNotBelongToCustomerException - "Account {0} does not belong to
       this customer."
  400  DuplicateBasketItemException - "Product offer {0} is already in the
       basket." (ayni prodOfrId+cmpgId ikilisi sepette birden fazla)
  400  OfferAlreadyActiveException - "Product offering {0} is already active
       on account {1}." (FR-014 IK-05: bu hesabin PROCESSING/FINISHED bir
       siparisinde zaten bu teklif var)

4.3) POST /api/v1/orders/{custOrdId}/items
--------------------------------------------------------------------------------
Offer Selection'da "Add to Basket" - WAIT durumundaki siparise yeni item
ekler.

Path param: custOrdId (Long)

Request body:
{ "prodOfrId": 2, "cmpgId": 1, "charVals": [] }

Basarili yanit: 201 Created, guncel OrderSummaryResponse (tum item'lar).

Kampanya indirimi ornegi (canli ortamda dogrulandi):
  prodOfrId=2 "Home Fiber 100Mbps" taban fiyati 299.90
  cmpgId=1 "Home Starter Bundle" %10 indirim -> price: 269.91 (otomatik
  hesaplanip item.price'a yaziliyor, cmpgName: "Home Starter Bundle")

Hatalar:
  404  OrderNotFoundException
  409  OrderNotEditableException (siparis WAIT disinda)
  400  DuplicateBasketItemException
  400  OfferAlreadyActiveException
  400  CampaignNotAppliedToOfferingException - cmpgId bu prodOfrId'ye
       gercekten uygulanmamissa (product-service'teki campaign-offerings
       eslesmesinde yoksa)
  404  Product offering / campaign product-service'te yoksa

4.5) PUT /api/v1/orders/{custOrdId}/configuration
--------------------------------------------------------------------------------
FR-015. Product Configuration ekraninda karakteristik/adres girildikce
(autosave) cagrilir. Idempotent (replace-all): her cagrida ilgili item'in
onceki karakteristikleri silinip yenileri yazilir.

Path param: custOrdId (Long)

Request body (var olan adresle):
{
  "items": [
    {
      "custOrdItemId": 2,
      "charVals": [ { "charId": 1, "charValId": 2, "val": null } ]
    }
  ],
  "addressId": 4,
  "newAddress": null
}

Request body (yeni adresle - addressId yerine):
{
  "items": [],
  "addressId": null,
  "newAddress": {
    "cityId": 5,
    "streetName": "Ataturk Cad.",
    "buildingName": "No:12 Kat:3",
    "addressDesc": "Ev"
  }
}

Alan aciklamalari:
  items[].custOrdItemId  Long, zorunlu - bu siparise ait olmali
  items[].charVals[]     ProdCharValRequest - charId zorunlu, charValId
                          verilirse charId'ye ait olmali, val opsiyonel
                          (max 255 karakter)
  addressId               Long, opsiyonel - musterinin/hesabinin VAR OLAN
                          adresi (addressId veya newAddress'ten TAM OLARAK
                          biri dolu olmali)
  newAddress               AddressInfoRequest, opsiyonel - yeni adres olusturur
    cityId                Long, zorunlu (lookup-service GNL_TP/CITY grubu)
    streetName            String, zorunlu, max 200
    buildingName          String, zorunlu, max 100
    addressDesc           String, zorunlu, max 200

ONEMLI - "yeni adres" olusturulunca ne olur:
  newAddress verildiginde contact-info-service'te YENI bir adres kaydi
  aciliyor ve bu adres MUSTERININ KENDI adres listesine (dataTypeId=
  CUSTOMER, rowId=custId) primary=false olarak ekleniyor - yani sadece bu
  siparise ozel kalmiyor, musterinin profilinde de gorunur ve ileride
  "var olan adres" olarak (addressId ile) tekrar secilebilir.

Basarili yanit: 200 OK
{
  ...,
  "serviceAddress": {
    "addressId": 4,
    "cityId": 5,
    "cityName": "Ankara",
    "streetName": "Ataturk Cad.",
    "buildingName": "No:12 Kat:3",
    "addressDesc": "Ev"
  },
  ...
}
Not: cityName lookup-service'ten ayrica cozulur; cityId lookup-service'te
bulunamazsa (eski/tutarsiz veri) istegi dusurmez, cityName sessizce null
doner.

Hatalar:
  404  OrderNotFoundException
  409  OrderNotEditableException
  404  OrderItemNotFoundException - custOrdItemId bu siparise ait degilse
  400  CharacteristicValueMismatchException
  400  AddressSelectionInvalidException - "Either addressId or newAddress
       must be provided, not both or neither."
  400  AddressNotBelongToCustomerException - "Address {0} does not belong
       to this customer." (addressId, musterinin/hesaplarindan birine ait
       degilse)

4.6) POST /api/v1/orders/{custOrdId}/finish
--------------------------------------------------------------------------------
FR-021. Review & Confirm'de Finish - WAIT -> MIDLWARE gecisini yapar,
product-service'te her item icin GERCEK Product'i senkron olarak
provizyonlar (fatura hesabi ekraninda urun gorunur hale gelir), Configuration'da
secilmis karakteristikleri de o urune isler, provizyon basariyla bitince
MIDLWARE -> FINISHED'e gecirip OrderSubmittedEvent'i (Kafka outbox) yayinlar.

Path param: custOrdId (Long)
Body: yok

Basarili yanit: 200 OK
{
  "custOrdId": 3,minor fixes in enpoints, exceptions and for already active account flo
  "ordStId": 53,
  "items": [
    {
      "custOrdItemId": 2,
      "prodId": 1,
      "prodOfrId": 1,
      "prodSpecId": 1,
      "ofrName": "Home Fiber 200Mbps",
      "prodName": "Home Fiber 200Mbps",
      ...
    }
  ],
  "serviceAddress": { ... },
  "totalAmount": 669.81
}

Onemli: adres set edilmemis bir siparis finish edilemez.

Hatalar:
  404  OrderNotFoundException
  409  OrderNotEditableException
  400  ServiceAddressMissingException - "Order {0} has no service address
       yet." (once 4.5 ile adres/konfigurasyon kaydedilmeli)
  502/503  Downstream call failed / unavailable - product-service provizyon
       cagrisi basarisiz olursa TUM transaction (MIDLWARE kaydi dahil) geri
       alinir; siparis asla gercekte urun olusmadan FINISHED'e dusmez.

5. IS KURALLARI OZETI (FR/BR referanslariyla)
--------------------------------------------------------------------------------
- BR-02 (varsayim): sepette ayni prodOfrId+cmpgId ikilisi tekrar edemez
  -> DuplicateBasketItemException (validate-basket / create / addItem).
- FR-014 IK-05: hesapta zaten aktif (PROCESSING/FINISHED) bir teklif tekrar
  eklenemez -> OfferAlreadyActiveException (validate-basket / create /
  addItem).
- FR-014 IK-01 (REQ - iliskili teklifler otomatik eklenmeli) ve IK-04
  (EXCL - cakisma engellenmeli): HENUZ IMPLEMENTE EDILMEDI. product-service
  tarafinda offering-bazli iliski sorgu endpoint'i (by-offering) yok, sadece
  CRUD var (ProductOfferingRelation, MANDATORY/OPTIONAL tipli - REQ/EXCL
  degil). Bu FR gap product-service tarafinda once cozulmeli.
- Kampanya indirimi: item.price, cmpgId varsa product-service'teki
  campaign-offerings eslesmesinin discountedPrice'i olarak hesaplanir;
  eslesme yoksa CampaignNotAppliedToOfferingException.
- Adres secimi: addressId XOR newAddress (ikisi birden veya hicbiri olmaz).
- Yeni adres, musterinin kendi adres listesine (CUSTOMER sahipligi,
  primary=false) kaydedilir - sadece siparise ozel kalmaz.
- finish, adres set edilmeden calisamaz (ServiceAddressMissingException).
- finish'teki provizyon (product-service Product olusturma + secilen
  karakteristiklerin islenmesi) SENKRON'dur; herhangi bir item'da hata
  olursa TUM islem (MIDLWARE gecisi dahil) rollback olur.
- Bilinen limitasyon (bilincli, deger verilmedi): finish icinde ayni
  siparis icin idempotent tekrar-provizyon koruma guard'i yok (ag hatasi
  sonrasi retry senaryosunda teorik cift-provizyon riski var, dusuk
  ihtimalli kabul edilip ertelendi).
